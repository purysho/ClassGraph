# v0.8.1 Desktop Transport Hotfix

**Branch:** `fix/v0.8.1-desktop-transport`  
**Started:** 2026-10-03  
**Status:** In progress

## Reported failure

Released v0.8.0 can show **"Failed to fetch"** when creating a manual class in the packaged desktop app.

## Root cause under correction

v0.8.0 loads a separate `desktop-renderer-bootstrap.js` module that monkey-patches
`window.fetch` so `/api/*` calls are redirected to the Electron preload IPC bridge.

If the main UI executes without that patch active, the app falls through to the browser-native
`fetch('/api/...')` while loaded from `file://`. There is deliberately no localhost server in the
Phase 8 desktop architecture, so the browser request fails.

## Hotfix plan

- [ ] Move desktop IPC selection into the ClassGraph API client itself.
- [ ] Never rely on a global `window.fetch` monkey-patch in the packaged app.
- [ ] Throw a ClassGraph-specific bridge error instead of attempting network fetch from `file://`.
- [ ] Keep browser/source development mode working over HTTP.
- [ ] Add direct transport tests.
- [ ] Add renderer/preload native self-test that actually loads the Electron window and invokes the bridge.
- [ ] Confirm manual class creation route works through IPC.
- [ ] Bump package to v0.8.1.
- [ ] Pass format, lint, strict TypeScript, tests, production audit.
- [ ] Pass Windows, Linux, macOS Apple Silicon and macOS Intel native build/self-test.
- [ ] Merge and publish v0.8.1.
