# v0.8.1 Desktop Transport Hotfix

**Branch:** `fix/v0.8.1-desktop-transport`  
**Started:** 2026-10-03  
**Status:** Complete — v0.8.1 released

## Reported failure

Released v0.8.0 can show **"Failed to fetch"** when creating a manual class in the packaged desktop app.

## Root cause

v0.8.0 loads a separate `desktop-renderer-bootstrap.js` module that monkey-patches
`window.fetch` so `/api/*` calls are redirected to the Electron preload IPC bridge.

If the main UI executes without that patch active, the app falls through to the browser-native
`fetch('/api/...')` while loaded from `file://`. There is deliberately no localhost server in the
Phase 8 desktop architecture, so the browser request fails.

## Hotfix plan

- [x] Move desktop IPC selection into the ClassGraph API client itself.
- [x] Never rely on a global `window.fetch` monkey-patch in the packaged app.
- [x] Throw a ClassGraph-specific bridge error instead of attempting network fetch from `file://`.
- [x] Keep browser/source development mode working over HTTP.
- [x] Add direct transport tests.
- [x] Add renderer/preload native self-test that actually loads the Electron window and invokes the bridge.
- [x] Confirm manual class creation route works through IPC.
- [x] Bump package to v0.8.1.
- [x] Pass format, lint, strict TypeScript, tests, production audit.
- [x] Pass Windows, Linux, macOS Apple Silicon and macOS Intel native build/self-test.
- [x] Merge and publish v0.8.1.

## Implementation evidence

- `src/app-client.ts` contains no direct `fetch(...)` calls; all five API call sites use `classGraphApiFetch(...)`.
- `src/api-client-transport.ts` selects the preload IPC bridge directly in packaged `file://` mode.
- If the preload bridge is absent in packaged mode, ClassGraph raises `CG-2014` instead of attempting a browser network request.
- Browser/source development still falls through to normal HTTP fetch.
- Native `--self-test` now loads the real renderer/preload bridge and invokes `POST /api/project/create` before packaging is accepted.
